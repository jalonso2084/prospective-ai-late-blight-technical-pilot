## Status
This is the canonical **execution design** for Step 3. It does not state that the Technical Pilot has already been completed.

## Primary question
> Can we reliably prepare equivalent scientific evidence, execute standardized AI evaluations, obtain structured forecasts, preserve every relevant input and output, characterize technical/model variability, and permanently freeze a reconstructable evaluation record?

The pilot tests measurement machinery, not prospective predictive validity.

## Frozen upstream authority
Prospective Cohort Enrollment & Information Boundary Protocol v1.0 governs eligibility, streams, Version Families, material revision, scientific t0, access, language, information boundary, metadata minimization, quarantine, and readiness. Step 3 does not reopen those scientific rules.

## Process Set and Evaluation Set
The Process Set contains 13 purposively chosen Version Families. Ten are Core; R019 is presently not evaluable under the primary condition because source full-text access is restricted; nine Core cases remain provisional Evaluation Set candidates. A case is promoted only after exact source-binary ingestion, CED creation, fidelity `PASS` or human-approved `PASS_WITH_DOCUMENTED_LIMITATION`, and viable delivery conditions.

## CED condition
Primary condition: `metadata-minimized + substantively complete scientific content + paper only + no live web`.

The source scientific binary is preserved and hashed before transformation. Scientific title, body, methods, results, discussion, conclusions, figures, tables, equations, references, and approved contemporaneous supplements remain. Focal authors/affiliations, journal branding, focal DOI, publication date, funding, acknowledgments, and obvious prestige/editorial metadata are removed where technically feasible without changing scientific evidence.

## Rubric
Pilot Rubric v0.2 separates present-paper assessment from three 36-month future-outcome forecasts. Translational timing remains exploratory. `CANNOT_ASSESS`, non-forecastable, and construct-ambiguous states are explicit alternatives to forced precision.

## Structured-output architecture
Project semantics are defined by a canonical schema. Provider-native schemas are adapters only. Every preserved raw response is subsequently checked by a deterministic canonical validator for structural and semantic consistency.

## Multilingual rule
Original-language CED is primary. Standardized English translation may be secondary. All free-text model outputs are returned in English; schema constants remain English.

## Information isolation
Every primary run uses a clean isolated context. No web, search, tools, project commentary, other model outputs, later paper versions, or future-outcome data are supplied.

## Prior internal knowledge
The project controls supplied evidence and live retrieval but cannot guarantee absence of prior internal model knowledge. Provider-reported knowledge cutoffs are recorded when available but are never treated as proof that a paper was absent from training.

## Future-information intrusion audit
The model is instructed not to use or mention later-version/outcome knowledge. After freezing, outputs are audited for identifiable information not contained in the CED. Such evidence is flagged; it is not interpreted as predictive accuracy.

## Model panel
Only real independently invoked providers may be claimed. One model may not simulate GPT/Claude/Gemini counterparts. Exact model identifiers and execution conditions are frozen immediately before live runs.

## Test–retest
Approximately four technically diverse Evaluation Set cases are repeated once per approved model under the same documented condition without exposing the first response. Repeats characterize variability; they are not ensemble members.

## Archive/freeze
Raw responses are primary immutable artifacts. Parsing, repair, and validation create derived artifacts and may never overwrite raw predictions. UTC timestamps and computed SHA-256 hashes are retained.

## Human gate
No scientific model execution occurs until exact source binaries, CED fidelity, v0.2 structured-output machinery, durable archive, and isolated provider paths are demonstrated and the Project Lead explicitly selects `APPROVE PILOT EXECUTION`.

## Exit criterion
Step 3 succeeds if the project can reconstruct what each model predicted, from exactly what evidence, under exactly what technical condition, without retrospective alteration. Correctness of the forecast is not an exit criterion.
